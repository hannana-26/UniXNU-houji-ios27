## 五、卡点:r68 CI 失败的真正原因(实锤,日志已存 `D:\yizhishouji\build\ci-45557105366-faillog.txt`)
- run `45557105366`:Run pre-build ✓、**Build kernel ✗**、Summary ✗(134 假失败)。
- 失败行:`…/tree/scripts/build-gop-legacy-display-27.py", line 422 … tomllib.loads((ROOT / 'profiles/os/ios-27.0.1-24A446/profile.toml').read_text())` → `FileNotFoundError: /Users/runner/work/UniXNU/UniXNU/out/houji/ios-27.0.1-24A446/houji_ios27/tree/profiles/os/ios-27.0.1-24A446/profile.toml`。
- **根因**:builder 里的 `ROOT` = `out/houji/<profile>/houji_ios27/tree`(**装配好的构建树**,不是 UniXNU 检出根)。树里有 `kits/sheng/*`(设备 package 装入,所以 r67 的 KeyStoreProbe 路径能用)、`scripts/*`、`build/xnu/…`、`.cache/xnu-work`,但**没有 `profiles/`,也没有 `refer/`**。

- 该次失败发生在 builder 刚开始 HID 段、**编译 NativeHidInput 之前**,所以 §六 的"头文件/vtable 重签"风险**还没被验证过**。

### 修法(给接手者,按序,一轮只改这一类)
1. **不要从 `ROOT/profiles` 读 pin。** 把 IOHIDFamily 的 git/ref/commit 直接写进 builder 常量。出处:`D:\yizhishouji\src\UniXNU-official\profiles\os\ios-27.0.1-24A446\profile.toml` 的 `[[source]] name = "IOHIDFamily"`:git=`https://github.com/apple-oss-distributions/IOHIDFamily.git`,ref=`IOHIDFamily-2238.120.5`;**commit 的 40 位全值请自己从该文件读出再写死,并在注释里标出处**(本文不转抄,避免抄错)。
2. **builder 自己克隆**:`git clone` 该 ref 到 `ROOT/build/refer-hid/IOHIDFamily`(已存在则复用),`git rev-parse HEAD` 与写死的 commit 比对,不符 `SystemExit`(等价 `pinned_source` 的校验但不依赖 `refer/`)。头文件拷贝逻辑(`IOHIDFamily/*.h`→`IOKit/hid`、`IOHIDSystem/IOKit/hidsystem/*.h`→`IOKit/hidsystem`)保持不变。CI runner 有网络(pre_build 已在 brew install)。
3. 删掉对 `ROOT/'profiles/...'` 和 `ROOT/'refer/IOHIDFamily'` 的引用;`prepare-storage-headers.py` 的 `pinned_source(source, revision)` 只是 git 校验函数,可继续 `load_helper` 复用,参数换成克隆路径即可(它要求工作区干净+HEAD 等于 revision)。
4. 提交前本地:WSL `/root/uvenv/bin/python3 -m py_compile scripts/build-gop-legacy-display-27.py`;确认 hid fixture 的 kernelcache=fa07057b。
5. 触发 CI(命令 §七)。**Build kernel 第一遍链接失败是预期**(两遍构建,首遍空链产 records),真失败看第二遍;Summary 134 假失败。
