## 0. 开工与收工
- **冷启动(十三):** 先读本文 + `交接文档_最新.md`,回复"已读并确认纲领"才许动手。
- **二次确认:** 开工前把交接文档"待办表"逐条报状态(完成/进行中/待开始/卡在哪);收尾再对一遍。
- **承诺闭环:** 说过要做的事,要么做完,要么写进交接待办并写明去向。违反=最高级违规。
- **只以文件交付:** 结论写进文件,对话里只给路径、摘要、待决策项。
- **落盘时机(十四):** porting.toml 当场写;四个触发点必须更新交接文档并 commit:①一轮/阶段完成 ②会话结束 ③刷机等高风险操作前 ④重大决策后。收尾顺序:porting.toml → 交接文档 → git commit push。标准:对话丢了,新会话读文件 5 分钟能接上。

## 1. 目标
小米14 houji(SM8650)移植 iOS 27.0.1(24A446,arm64e),基于 UniXNU,必须是 iOS 不是 iPadOS。用户是外行:简体中文、大白话、不客套、少让用户录屏。

## 2. 安全红线
1. 碰手机只许:`fastboot boot`、刷 `userdata`(先给完整命令并得到明确确认)、只读的 `fastboot reboot fastboot`/`fastboot fetch`。fastbootd 里只许 fetch/getvar/reboot。禁止刷其他分区、erase、format、set_active。
2. 每次 `fastboot boot` 前等用户说"开始",并确认"录像准备好了吗"。
3. **测试前判据链必须先验一遍(2026-11-27 用户第二次批评后加入 §4 第 13 条):没准备好不许让用户测。**
4. 失败先存镜像和日志再改;产物不覆盖,新产物新编号 rN。
5. 证据三类:实机验证 / 仅构建通过 / 作者自述;没日志佐证的标"推测"。

## 3. 纲领(用户决定,AI 无权改)
- **一、路线锁定:** APFS + 官方 IPSW,挂真 iOS 系统卷(SHNGROOT,同 sheng)。HFSX 只是备胎,切换要用户决定。
- **二、七阶段顺序:** UEFI→菜单→Payload→DarwinBoot→内核入口→存储根卷→用户态;当前阶段没过不做下一阶段。(现处第 7 阶段=用户态逐个驱动。)
- **三、官方 CLI/CI 为主链:** 正式构建走官方 CLI 和 CI;探针/调试脚本可放 `work\`,但须幂等、可复现、记命令与哈希;要当"通过"证据的先落进设备仓库。
- **四、四源强制扫描:** 动任何子系统前按序扫并记录("已扫无可借鉴"或"借了 XX"):①官方同 SoC(`UniXNU-sheng`、`UniXNU-official`)②同设备 houji(lonzzi/Kizashi3/hannana/sakayorilroha;nian0114 是否列入待用户定)③同代机型(shennong 三家、fuxi、cupid、peridot、`src\community\*`)④`src\aston`。读到补丁的前提类注释,逐条对照本仓配置写"满足/不满足+行号",不满足当场立案。
- **五、porting.toml 字段齐:** inputs/configuration/procedure/findings/completion/evidence(+limits/next_action),缺一=未完成。
- **六、失败先留现场:** 同红线 4、5。
- **七、QEMU 优先:** 官方 QEMU 只覆盖 1–5 阶段;launchd 之后只能真机,findings 里写明原因。
- **八、引用路径先核实存在。**
- **九、不会就直说:** 不许用"再试一轮"拖;请不请外援由用户定。
- **十、git 与文件是唯一状态:** 对话里的不算数;交接文档固定名覆盖更新;commit 不破坏 `unixnu.lock`。
- **十六、硬仗协议(仅用户决定请外援时):** 交接文档写五栏(环境/已发生/已排除/卡点/验收标准),新开会话只喂交接+porting.toml+一句卡点,限时限量,解决后写回并停止,验收在用户。(模型/渠道选择由用户处理,AI 不讨论。)
- **十七、轮子优先+开工三查:** 造任何东西前先在四源找现成的。每轮构建或碰手机前开头写三行:本轮动作 / 借了谁的什么 / 四源扫描记录在哪。写不出=不许动手。
- **十八、每轮三问:** 出结论或烧机的轮次,报告开头写:①确认了什么 ②凭什么信(文件/命令输出/哈希/日志行)③推翻了什么(旧→新→依据,三份记录同步+commit 号)。结论标"实锤/推测/未确认";status 只随证据动。

## 4. 干活方法
1. 借用前核适用性(内核 sha256/设备/OS 版本)。
2. panic 流程:抽帧→OCR→`work\sym.py`→`work\fsent.py`→`work\dis46.py`→**全库 grep panic 原句**→扫四源→再动手。
3. 一轮只改一类,先写清预期现象。
4. 启动前本地自检(chkadt/gatecheck 等),结果入记录。
5. 每跑一轮立刻追加进度记录:时间、镜像名+sha、现象、结论、下一步。
6. 汇报诚实,推测不写成已验证。
7. 结论被推翻当天,清理全部衍生物(补丁/参数/探针/台账/镜像),要留的写理由+复评条件。
8. 编辑 TOML/大数组后当场用 tomllib 校验,过了才 commit。
9. 借来的源码逐字节保留(哈希入库);冲突用带注释的 -Wno 标志解决,适配只落在标注的适配文件。
10. 整文件重写后逐个核对"声明 vs 使用"。
11. late.a 归档里文件级 static 必须 POD 零初始化(禁静态 OSSharedPtr)。
12. 长期运行的驱动必须有周期心跳 printf(stage/error/计数),一次性 init 行会被日志环冲掉。
13. **(v4 新增)判读纪律三条**(来自 2026-11-27 三次同型错误):①判画面统计前先问用户做了什么操作,并排除页面内容差异;②判读回记录属于哪次启动,用 commit 计数/写入器时间/会话长度三交叉,不许单凭时间戳;③**让用户测试前,把"会看到什么→怎么读→读数怎么判"整条链用已有数据验算一遍(含日志量、时序、记录容量),验不通就先改方案,不许让用户试错。**
14. **(v4 新增)pwsh 处理中文文件:** 读必须 `-Encoding UTF8` 或改用编辑工具;commit 前看一眼 diff;提交信息含引号用单引号包;文件名不含冒号。
